# 👔 날씨 및 목적 기반 외출 코디네이터

자바 **SOLID 원칙**과 **디자인 패턴**을 적용하여 만든 날씨와 일정에 맞는 최적의 코디를 추천하는 콘솔 시뮬레이터입니다.

---

## 📋 프로젝트 개요

매일 아침 날씨와 일정에 맞춰 옷을 고르는 시간을 줄여주는 코디네이터입니다.

- **타겟**: 오늘 어떤 옷을 입어야 할지 고민하는 사람들
- **목적**: 날씨와 일정에 맞는 옷을 자동 추천
- **핵심 가치**: TPO 미스매치 방지, 아침 시간 절약

---

## 🏗️ 프로젝트 구조

### 핵심 클래스 (10개)

| 클래스 | 역할 | SOLID 연결 |
|--------|------|-----------|
| **Main** | 프로그램 진입점, 의존성 조립(DI) | DIP: 구체 클래스가 아닌 인터페이스/팩토리에 의존 |
| **OutfitRecommender** | 사용자 입출력 + 추천 흐름 제어 | SRP: View(출력) 책임만 담당 |
| **RecommendStrategy** | 추천 알고리즘 전략 인터페이스 | OCP: 새 전략 추가 시 기존 코드 수정 불필요 |
| **RecommendStrategy.Basic** | 완전 탐색 기반 기본 전략 | - |
| **Wardrobe** | 사용자 옷장 보관 | SRP: "보관"만 담당 |
| **Wardrobe.Factory** | 옷 아이템 생성 (중첩 클래스) | SRP: 생성 로직 분리 |
| **Outfit** | 코디 세트 (상의+하의+아우터) | 순수 모델, 출력 로직 없음 |
| **ClothingItem** | 개별 옷 아이템 | LSP: 불필요한 상속 제거, 단일 클래스화 |
| **ClothingItem.Property** | 옷 특성(별볼너스) (중첩 클래스) | 캡슐화: 속성은 아이템과 밀접하게 결합 |
| **Situation** | 오늘 상황 (날씨+일정+기온) | 가중치 계산 책임 담당 |
| **Category** | 카테고리 enum (상의/하의/아우터) | 타입 안정성, 이모지 관리 |
| **Weather** | 날씨 enum | 타입 안정성, 한글명/이모지 관리 |
| **Schedule** | 일정 enum | 타입 안정성, 한글명/이모지 관리 |

> 총 10개의 `.java` 파일로 구성 (리팩토링 전 17개 → 10개 압축)

---

## 🎨 디자인 패턴

| 패턴 | 적용 위치 | 설명 |
|------|----------|------|
| **Strategy** | `RecommendStrategy` | 추천 알고리즘을 인터페이스로 추상화, 교체 가능 |
| **Factory** | `Wardrobe.Factory` | 옷 아이템 생성 로직을 중첩 클래스로 캡슐화 |
| **Enum** | `Category`, `Weather`, `Schedule` | 타입 안전한 상수 관리 + 메타데이터(이모지) |
| **Dependency Injection** | `Main` | `OutfitRecommender` 생성 시 전략 객체 주입 |

## 🎮 사용 방법

### 실행 (Mac/Linux)
```bash
./run.sh
```

### 실행 (Windows)
```bash
run.bat
```

### 수동 실행
```bash
# 컴파일 (.class → class/ 폴드러)
javac -d class *.java

# 실행
java -cp class Main
```

### 추천 진행
1. 프로그램 실행
2. 옷장 목록 확인 (상의 2벌, 하의 2벌, 아우터 3벌)
3. 오늘의 **날씨** 선택 (맑음, 비, 눈, 추움, 더움, 바람)
4. 오늘의 **일정** 선택 (정장/회의, 캐주얼 외출, 울동, 데이트)
5. 오늘의 **기온** 입력 (-10℃ ~ 40℃)
6. 최적의 코디 자동 추천 및 적합도 점수 확인

## 📊 적합도 계산 시스템

### 기본 공식
```
기본 점수 = 아이템 능력치 × 상황 가중치
총 적합도 = Σ(상의 점수 + 하의 점수 + 아우터 점수) + 특성 별볼너스
```

### 상황별 가중치
| 조건 | 보온 | 방수 | 격식 | 편안 |
|------|------|------|------|------|
| 기온 < 5℃ | 2.5× | - | - | - |
| 기온 < 15℃ | 1.5× | - | - | - |
| 기온 > 30℃ | **-1.5×** | - | - | - |
| 비 오는 날 | - | 3.0× | - | - |
| 눈 오는 날 | 1.5× | 2.0× | - | - |
| 정장/회의 | - | - | 2.5× | 0.7× |
| 울동 | - | - | 0.7× | 3.0× |

### 🔥 더위 페널티 (핵심 개선)
> **30℃ 초과 + 아우터 + 보온성 > 0** 아이템: **-500점**

32℃ 더운 날 트렌치코트를 입으라는 비현실적 추천을 방지합니다.

### 점수 구간 피드백
| 점수 | 피드백 |
|------|--------|
| 900점 이상 | 🌟 완벽한 코디! |
| 700~899점 | 👍 훌륭한 코디! |
| 500~699점 | 😊 무난한 코디입니다. |
| 500점 미만 | 🤔 조금 아쉬운 코디... |

## 🏛️ SOLID 원칙 적용

| 원칙 | 적용 내용 |
|------|-----------|
| **SRP** | 모델(`Wardrobe`, `Outfit`, `ClothingItem`)에서 **콘솔 출력 코드 제거**. 출력은 `OutfitRecommender`가 전담. |
| **OCP** | `RecommendStrategy` 인터페이스로 추상화. 새 전략 추가 시 기존 코드 수정 불필요. 점수 등급 메시지도 데이터 기반화. |
| **LSP** | `Top`/`Bottom`/`Outer` 서브클래스 제거. `ClothingItem` 단일 클래스로 대체하여 **불필요한 상속 제거**. |
| **ISP** | `RecommendStrategy`는 단 하나의 메서드만 정의. 작고 focused한 인터페이스 유지. |
| **DIP** | `Main`이 구현체를 생성해 주입. `OutfitRecommender`는 `RecommendStrategy` **인터페이스만** 의존. |
